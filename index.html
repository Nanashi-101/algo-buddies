01

🍳 Algorithms & Data Structures

From: Algorithms & Complexity Analysis

  • Algorithm = a finite sequence of well-defined instructions that solves a problem. Slide example: largest of 5, 12, 3, 20, 8 → keep a "best so far" → 20.
  • 6 traits: Input · Output · Definiteness (clear steps) · Finiteness (it stops) · Effectiveness (doable steps) · Correctness (right answer).
    Mnemonic: "I Offer Delicious Fresh Eclairs, Cutie"
  • Data structure = a way to organise and store data so it can be accessed and modified efficiently (array, linked list, stack, queue, tree, graph).
  • Together: the data structure stores, the algorithm processes — e.g. binary search (algorithm) on a sorted array (data structure).
  • Design process: understand the problem → inputs/outputs → pick an approach → pseudocode/flowchart → analyse correctness & efficiency → implement, test, improve.
🍳 A recipe is an algorithm (clear steps, ends with a dish). The pantry/fridge is the data structure — it decides how quickly you can grab an ingredient.

🎤 Sample oral Q&A

QWhat is the difference between an algorithm and a data structure?

AAn algorithm is a set of steps that processes data to solve a problem; a data structure organises and stores the data. They work together — binary search is the algorithm, the sorted array is the structure it runs on.

QHow would you design an algorithm?

AUnderstand the problem, identify inputs and expected outputs, choose an approach (e.g. linear vs binary search depending on whether the data is sorted), write pseudocode or a flowchart, analyse correctness and efficiency, then implement, test and improve.

⭐ Most important — expect this one

QWhat is an algorithm and what characteristics must it have?

AA finite sequence of well-defined instructions that solves a problem. It needs input, output, definiteness (clear steps), finiteness (terminates), effectiveness (steps are executable) and correctness (gives the intended result).

🍬 Summary

Algorithm = finite, clear steps → correct output. Data structure = where the data lives. The algorithm works on the structure.

  • 6 traits: I-O-D-F-E-C
  • Design: understand → approach → pseudocode → analyse → implement
  • Choose the approach from the data (sorted? → binary search)

⏱️ Time & Space Complexity, Big O / Ω / Θ

From: Algorithms & Complexity Analysis

  • Complexity analysis = how much time or memory an algorithm needs as the input size n grows.
  • Time counts basic operations, not seconds. One loop of n → O(n) (linear). Nested loops n × n → O(n²) (quadratic).
  • Space = extra memory growth: a few variables O(1) · copy of a list O(n) · n×n matrix O(n²) · recursion stack of binary search O(log n).
  • Best / average / worst — linear search for 30 in [10, 20, 30, 40, 50]: best = found first (Θ(1)); average ≈ (n+1)/2 comparisons (Θ(n)); worst = last or missing (Θ(n)).
  • Asymptotic notation (large n, machine-independent):
    O = upper bound ("at most")Ω = lower bound ("at least")Θ = tight bound ("exactly")
    Big O is not automatically "worst case".
🤝 Party with n guests: greeting each one = O(n); everyone greeting everyone ≈ n² handshakes = O(n²). Space: carrying a notebook O(1) vs photocopying the whole library O(n).

🎤 Sample oral Q&A

QDoes time complexity measure running time in seconds?

ANo. It measures how the number of basic operations grows with input size n, so it does not depend on the machine or language.

QGive the best, average and worst case of linear search.

ABest: target is first — one comparison, Θ(1). Average: about (n+1)/2 comparisons — Θ(n). Worst: target is last or missing — n comparisons, Θ(n).

⭐ Most important — expect this one

QExplain Big O, Big Omega and Big Theta.

ABig O is an asymptotic upper bound (grows no faster than), Big Omega is a lower bound (grows at least as fast), and Big Theta is a tight bound — both at once. Example: a loop that always runs exactly n times is Θ(n), so it is also O(n) and Ω(n).

🍬 Summary

Complexity = how cost grows with n. O is the ceiling, Ω the floor, Θ the exact growth.

  • Count operations, not seconds
  • Single loop O(n) · nested loops O(n²)
  • Best/avg/worst ≠ O/Ω/Θ — different questions

🧩 P, NP, NP-hard & NP-complete

From: Algorithms & Complexity Analysis

  • We talk about decision problems (answer = yes / no).
  • P — solvable by a deterministic algorithm in polynomial time (O(n), O(n²), O(n³)…). e.g. value in a sorted array? path between two vertices? is the graph connected?
  • NP — a proposed "yes" answer can be verified in polynomial time. e.g. Hamiltonian cycle: easy to check a given cycle, hard to find one. P ⊆ NP.
  • NP-hard — every NP problem reduces to it in polynomial time → "at least as hard as everything in NP". It may be outside NP and need not be a decision problem (e.g. optimisation TSP).
  • NP-complete = in NP and NP-hard. e.g. SAT, 3-SAT, Hamiltonian cycle (decision). Solve one in polynomial time ⇒ P = NP.
🧩 Sudoku (as an analogy): checking a finished grid is quick (verify), but finding the solution for a huge blank grid is the hard part (solve).

🎤 Sample oral Q&A

QDoes "NP" mean "not polynomial"?

ANo — it stands for Nondeterministic Polynomial time: problems whose yes-answers can be checked in polynomial time. P sits inside NP, and whether P = NP is still open.

QIs every NP-hard problem in NP?

ANo. NP-hard only says the problem is at least as hard as every NP problem. It may be outside NP or not a decision problem — e.g. the optimisation version of the travelling salesperson problem.

⭐ Most important — expect this one

QDefine P, NP, NP-hard and NP-complete and say how they relate.

AP: decision problems solvable in polynomial time. NP: yes-answers verifiable in polynomial time, and P ⊆ NP. NP-hard: every NP problem reduces to it, so it is at least as hard. NP-complete: both in NP and NP-hard (e.g. SAT). If any NP-complete problem is solved in polynomial time, then P = NP.

🍬 Summary

P = easy to solve. NP = easy to verify. NP-hard = at least as hard as all of NP. NP-complete = NP ∩ NP-hard.

  • P ⊆ NP
  • NP-complete = in NP and NP-hard
  • One poly-time NP-complete algorithm ⇒ P = NP

🚂 Arrays & Linked Lists

From: Fundamental Data Structures

  • Array = linear structure of elements (usually same type) at indexed positions, typically in contiguous memory. marks[0]=70, marks[2]=90.
  • Linked list = nodes, each holding data + a pointer to another node; nodes need not be contiguous. Head → … → NULL.
  • Types: singly (next only) · doubly (prev + next, two-way) · circular (last points back to first).
  • Operations: traverse · insert (re-link) · delete (bypass the node) · search · update.

🎬 Array = a cinema row with numbered seats: jump straight to seat 7 — but squeezing someone into the middle makes everyone shift. Linked list = a scavenger hunt: each clue tells you where the next is, so to reach clue 5 you walk through 1–4.

🎤 Sample oral Q&A

QWhat are the types of linked lists?

ASingly (each node points to the next), doubly (links to previous and next, so two-way traversal), and circular (the last node points back to the first instead of NULL).

QWhy is inserting in the middle cheap for a linked list but costly for an array?

AAn array must shift later elements to make room. A linked list only re-links a couple of pointers — though you still need O(n) traversal to find the spot unless you already hold a reference to it.

⭐ Most important — expect this one

QCompare arrays and linked lists.

AArrays: contiguous memory, fast index access, good locality, but fixed size and costly middle insert/delete. Linked lists: nodes joined by pointers, grow and shrink dynamically, cheap re-linking, but no direct indexing, extra pointer memory and poorer locality. Arrays suit fixed-size, index-heavy data; linked lists suit collections whose size changes a lot.

🍬 Summary

Array = fast index, rigid size. Linked list = flexible size, slow to reach the i-th item.

  • Array: O(1) access, shifting on insert
  • Linked list: pointers, no indexing
  • Singly · doubly · circular

🧋 Stacks & Queues

From: Fundamental Data Structures

  • Stack = LIFO (Last In, First Out). push · pop · peek/top · isEmpty. Errors: overflow (push onto a full fixed-size stack), underflow (pop from an empty one).
  • Queue = FIFO (First In, First Out). enqueue (rear) · dequeue (front) · front/peek · isEmpty.
  • Queue types: simple · circular (end wraps to start so freed slots are reused) · priority (served by priority, not arrival) · deque (insert/remove at both ends).
  • Look ahead: DFS uses a stack, BFS uses a queue.
🥞 Stack: pancakes, plates, Ctrl+Z undo. 🧋 Queue: bubble-tea line, tasks waiting to be processed. Priority queue = hospital ER triage. Deque = a train you can board from either end.

🎤 Sample oral Q&A

QWhat are stack overflow and underflow?

AOverflow: pushing onto a full fixed-capacity stack. Underflow: popping from an empty stack.

QWhat is the point of a circular queue?

AIn a simple array queue, the front slots freed by dequeues are wasted. A circular queue wraps the end back to the start so unused positions can be reused.

⭐ Most important — expect this one

QCompare a stack and a queue.

AA stack is LIFO — insert and remove at the top (push/pop), e.g. undo in an editor. A queue is FIFO — insert at the rear, remove at the front (enqueue/dequeue), e.g. tasks waiting for processing. DFS uses a stack, BFS uses a queue.

🍬 Summary

Stack = last in, first out. Queue = first in, first out.

  • Stack: push / pop / peek
  • Queue: enqueue / dequeue
  • Variants: circular · priority · deque

🌳 Trees, Binary Trees & BST

From: Fundamental Data Structures

  • Tree = hierarchical, non-linear: nodes joined by edges. Root (top) · parent/child · siblings · leaf (no children) · internal node · subtree.
  • Depth = edges from root to the node. Height = edges on the longest path down to a leaf (a leaf has height 0). Degree = number of children.
  • Binary tree: ≤ 2 children (left, right). Full: 0 or 2 children Complete: all levels full except last, filled left→right Perfect: all internal have 2 kids, leaves same depth Balanced: height ~ O(log n) Skewed: a chain
  • BST: at every node, left subtree < node < right subtree.

📁 Folders inside folders, a family tree, an org chart. BST = the guess-my-number game: higher → go right, lower → go left.

🎤 Sample oral Q&A

QWhat is the difference between a binary tree and a binary search tree?

AA binary tree only limits each node to two children. A BST adds an ordering rule at every node: left subtree values are smaller, right subtree values are larger.

QWhat is the difference between depth and height, and between full, complete and perfect?

ADepth counts edges from the root down to the node; height counts edges on the longest path from the node down to a leaf. Full: every node has 0 or 2 children. Complete: all levels full except possibly the last, filled left to right. Perfect: all internal nodes have two children and all leaves are at the same depth.

⭐ Most important — expect this one

QState the four tree traversals. What does inorder give on a BST?

APreorder: Root → Left → Right. Inorder: Left → Root → Right. Postorder: Left → Right → Root. Level-order: level by level. On a BST, inorder visits keys in sorted ascending order — for our tree 20, 30, 40, 50, 60, 70, 80.

🍬 Summary

Tree = parent-child hierarchy. BST = left smaller, right larger, so lookup follows one path.

  • Height of a leaf = 0
  • Pre: Root-L-R · In: L-Root-R · Post: L-R-Root
  • Inorder of BST = sorted

🔎 Searching: Linear & Binary

From: Search & Sort Algorithms

  • Linear search: check elements one by one until found or the list ends. Works on unsorted data. Best O(1) · worst O(n) (not found) · extra space O(1).
  • Binary search: needs sorted data. mid = (start+end)/2. If A[mid] < target → start = mid+1; if A[mid] > target → end = mid−1. Best O(1) (target is mid) · worst O(log n) · iterative space O(1) (recursive: O(log n) stack).
  • Trace: sorted [1, 3, 4, 7, 11, 13], target 11 → mid = index 2 (value 4) too small → go right → mid = index 4 (value 11) ✔ found in 2 steps.
🧦 Linear = hunting for one sock in a messy drawer. 📖 Binary = looking a word up in a dictionary; guessing a number 1–100 takes ≤ 7 guesses.

🎤 Sample oral Q&A

QWhy does binary search need sorted data?

AComparing with the middle only tells you which half to discard if the order is known. In unsorted data the target could be in either half.

QWhy is binary search O(log n)?

AEach step halves the remaining range: n → n/2 → n/4 → … → 1, which takes about log₂ n steps.

⭐ Most important — expect this one

QCompare linear search and binary search.

ALinear: works on any data, checks one by one, O(n) worst case, O(1) space. Binary: sorted data only, halves the range each step, O(log n) worst case, O(1) space iteratively. Use linear for small or unsorted data and binary for large sorted arrays with index access.

🍬 Summary

Linear = simple, any order, O(n). Binary = sorted only, halve each time, O(log n).

  • Binary needs sorted + indexed access
  • Worst case: value not present
  • Best case binary: target is the middle

🧺 Sorting: Bubble, Selection, Insertion, Merge, Quick

From: Search & Sort Algorithms

Sorting = arranging data in a chosen order (ascending / descending). Five classics:

🫧Bubble sort

Compare neighbours, swap if out of order; repeat. Big values "bubble" to the end.

🧸 Bubbles floating up

Stable · best O(n) with early-stop flag · for teaching / tiny lists

🎯Selection sort

Find the minimum of the unsorted part, swap it to the front of that part; boundary moves right.

🧸 Picking the shortest kid for the class photo, again and again

Always O(n²) comparisons · O(1) space

🃏Insertion sort

Take the next element and insert it into its correct place in the sorted part on the left.

🧸 Sorting playing cards in your hand

Best O(n) on nearly sorted data · great for small inputs

🥞Merge sort

Split into halves until size 1, sort, then merge sorted halves.

🧸 Merging two sorted piles of exam papers

Always O(n log n) · O(n) extra space · stable

⚡Quick sort

Pick a pivot; smaller elements left, larger right; recurse on both sides.

🧸 "Shorter than Alex → left, taller → right"

Avg O(n log n) · worst O(n²) with bad pivots · ~O(log n) stack

📚 Insertion = arranging cards in hand. Merge = combining two sorted queues. Quick = splitting a class into "shorter / taller than the pivot kid" and repeating.

🎤 Sample oral Q&A

QWhen does quick sort degrade to O(n²)?

AWhen the pivot keeps splitting badly — e.g. always the smallest or largest element — so the partitions are very unbalanced. A good (e.g. random) pivot makes this unlikely.

QWhy use quick sort if merge sort guarantees O(n log n)?

AQuick sort is often faster in practice and needs little extra memory (about O(log n) stack), whereas merge sort needs O(n) extra space. Merge sort wins when you need guaranteed time or stability.

QWhat is the best case of bubble sort and insertion sort?

AO(n) when the data is already sorted (for bubble sort this assumes an optimised version that stops when no swaps occur).

⭐ Most important — expect this one

QCompare the five sorting algorithms and say which you would pick when.

ABubble, selection and insertion are O(n²) on average and worst case with O(1) space (bubble and insertion are O(n) best case). Merge sort is O(n log n) always but uses O(n) extra space. Quick sort is O(n log n) on average, O(n²) worst case. Pick insertion for small or nearly sorted data, merge for large data with predictable time, quick for large data with practical speed.

🍬 Summary

Simple sorts are O(n²). Merge guarantees O(n log n) (extra memory). Quick is usually fastest but can hit O(n²).

  • Merge sort: O(n) extra space, stable
  • Quick sort: pivot choice decides everything
  • Insertion sort loves nearly-sorted data

🪆 Recursion & Recurrence Relations

From: Recursion & Algorithm Design

  • Recursion = a function calls itself on a smaller input. Base case stops it; recursive case shrinks the problem. The call stack keeps the pending calls. Missing base case → infinite recursion.
  • Types: direct · indirect (A↔B) · tail (call is the last action) · tree/multiple (several calls per call).
  • Recursion vs iteration: factorial is O(n) time both ways, but a loop saves stack space.
def factorial(n):
    if n == 0: return 1            # base case
    return n * factorial(n - 1)    # recursive case

factorial(4) calls ↓ 4×f(3) → 3×f(2) → 2×f(1) → 1×f(0) → f(0)=1 ↑ returns 1 → 1 → 2 → 6 → 24

  • Recurrence = T(n) models the cost of a recursive algorithm.
    T(n)=T(n−1)+c → O(n)T(n)=T(n−1)+n → Θ(n²)T(n)=T(n/2)+c → O(log n)T(n)=2T(n/2)+n → Θ(n log n)
  • Solve by: expansion/substitution · recursion tree (sum work per level) · Master Theorem for T(n)=aT(n/b)+f(n) (check its assumptions).
  • bonus Master cases: compare f(n) with nlogba — f smaller → Θ(nlogba); equal → Θ(nlogba log n); f larger (with regularity) → Θ(f(n)). Merge sort: a=2, b=2, f=n → equal → Θ(n log n).
🪆 Matryoshka dolls: open a doll, find a smaller doll, repeat — until the tiniest solid doll (the base case). Then put them back together from the inside out.

🎤 Sample oral Q&A

QWhat happens if a recursive function has no base case?

AIt never stops: calls keep piling onto the call stack until memory runs out (stack overflow) — infinite recursion.

QSolve T(n) = T(n−1) + n.

AExpand: T(n) = n + (n−1) + … + 1 = n(n+1)/2, so T(n) = Θ(n²).

QRecursion or iteration — what are the trade-offs?

ABoth can express the same algorithm (factorial is O(n) time either way) but recursion uses call-stack space while a simple loop saves it. Recursion is natural for trees, divide-and-conquer and backtracking.

⭐ Most important — expect this one

QWhat is recursion? Explain base case and recursive case, and trace factorial(4).

AA function calling itself on a smaller input. The base case (n = 0 → 1) stops the calls; the recursive case (n × factorial(n−1)) shrinks the problem. Calls go down 4 → 3 → 2 → 1 → 0, the base case returns 1, and results return upward: 1, 1, 2, 6, 24.

🍬 Summary

Recursion = solve by solving smaller copies, with a base case to stop. Recurrences give the cost.

  • Always: base case + progress toward it
  • T(n−1)+n → Θ(n²) · T(n/2)+c → O(log n)
  • Master Theorem: aT(n/b)+f(n)

🍕 Divide & Conquer

From: Recursion & Algorithm Design

  • Divide into smaller subproblems → Conquer each recursively (solve tiny ones directly) → Combine the answers. Cost: T(n) = aT(n/b) + f(n).
  • Works best when subproblems are independent and combining is cheap.
AlgorithmWhere the work happensTime
Binary searchone half is discarded each stepO(log n)
Merge sortthe merge (combine) stepΘ(n log n)
Quick sortthe partition (divide) stepexpected Θ(n log n), worst Θ(n²)
🍕 Cut a huge pizza (or a group report) into slices, let each friend handle one, then combine the results.

🎤 Sample oral Q&A

QWhen does divide and conquer work well?

AWhen subproblems are independent and combining their answers is cheap. If subproblems overlap, dynamic programming is the better tool.

QWhere is the real work in merge sort vs quick sort?

AMerge sort: splitting is trivial and the merge step does the work (Θ(n)). Quick sort: the partition step does the work and combining is trivial.

⭐ Most important — expect this one

QExplain divide and conquer with an example and its recurrence.

ADivide the problem, conquer the subproblems recursively, combine the results; the cost is T(n) = aT(n/b) + f(n). Merge sort: T(n) = 2T(n/2) + Θ(n) = Θ(n log n). Binary search: T(n) = T(n/2) + c = O(log n).

🍬 Summary

Split → solve → combine. Great for independent subproblems.

  • Examples: binary search, merge sort, quick sort
  • T(n) = aT(n/b) + f(n)
  • Overlapping subproblems → use DP instead

🪙 Greedy Algorithms

From: Recursion & Algorithm Design

  • Greedy = build the solution one step at a time, always taking the best currently feasible choice. Simple and fast — but a locally best choice is not automatically globally optimal.
  • Needs a proof (exchange argument, induction, structure). Look for greedy-choice property + optimal substructure.
  • Coin change: {25, 10, 5, 1}, amount 36 → 25+10+1 = 3 coins ✔. But {1, 3, 4}, amount 6 → greedy 4+1+1 = 3 coins, yet 3+3 = 2 coins ✘. One counterexample kills "always optimal".
  • Activity selection: sort by finish time, take the earliest-finishing, then the next that starts after it ends. A(1,3), C(4,6), D(6,8), F(8,10) → 4 activities. Time O(n log n) (O(n) if pre-sorted).
💵 A cashier handing back change with the biggest notes first. 🎬 Film festival with one screen: always pick the film that ends earliest so you can fit the most films.

🎤 Sample oral Q&A

QDoes greedy coin change always work?

ANo. For {25, 10, 5, 1} it works (36 → 25+10+1), but for {1, 3, 4} and amount 6 greedy picks 4+1+1 = 3 coins while 3+3 = 2 coins is optimal. A single counterexample disproves universal optimality.

QIn activity selection, what do you sort by and why?

ABy finish time. Taking the earliest-finishing activity leaves the most room for the rest, and an exchange argument proves it is safe. Example A(1,3), C(4,6), D(6,8), F(8,10) → 4 activities.

⭐ Most important — expect this one

QWhat is a greedy algorithm and when is it correct?

AIt builds a solution by repeatedly taking the best currently feasible choice. It is only correct when the problem has the greedy-choice property and optimal substructure, usually shown with an exchange argument — an intuitive rule is not enough (coin change on {1, 3, 4} fails).

🍬 Summary

Greedy = grab the best option now. Fast, but only valid with a proof.

  • Works: activity selection (sort by finish)
  • Fails: coin change {1,3,4}, amount 6
  • Counterexample is enough to disprove

📝 Dynamic Programming

From: Recursion & Algorithm Design

  • DP = store answers to subproblems and reuse them instead of recomputing.
  • Needs: overlapping subproblems (same smaller problem recurs) + optimal substructure (best answer built from best sub-answers).
  • Top-down memoization = recursion + cache. Bottom-up tabulation = fill a table in dependency order. Start with a precise state definition.
  • Fibonacci: naive recursion recomputes F(3), F(2)… → exponential. DP → O(n) time; space O(n) → O(1) if you keep only the last two values.
  • Greedy vs DP: greedy commits to a local choice (needs a proof); DP evaluates states and combines stored results. Greedy: activity selection. DP: 0/1 knapsack, LCS (O(mn)).
dp[0], dp[1] = 0, 1
for i in range(2, n + 1):
    dp[i] = dp[i-1] + dp[i-2]
📝 Doing 7 × 8 once and writing it on a sticky note, so the next 100 times you just read it.

🎤 Sample oral Q&A

QWhat is the difference between memoization and tabulation?

AMemoization is top-down: recursion plus a cache of computed answers. Tabulation is bottom-up: fill a table in dependency order, with no recursion.

QGreedy vs dynamic programming?

AGreedy commits to the locally best choice without comparing all alternatives and needs a correctness proof. DP evaluates states and combines stored results across alternatives. Activity selection is greedy; 0/1 knapsack and LCS are DP. Choose by problem structure, not just because it is an optimisation problem.

⭐ Most important — expect this one

QWhat is dynamic programming and which two properties are needed?

ADP stores answers to subproblems and reuses them. It needs overlapping subproblems and optimal substructure. Example: Fibonacci drops from exponential (naive recursion) to O(n) time, and O(1) space if only the previous two values are kept.

🍬 Summary

DP = remember subproblem answers. Memoization (top-down) or tabulation (bottom-up).

  • Overlapping subproblems + optimal substructure
  • Define the state first
  • Fibonacci: exponential → O(n)

🎒 0/1 Knapsack (DP)

From: 0/1 Knapsack

  • Problem: each item has a weight and a value; capacity W. Take an item whole (1) or leave it (0) — no fractions. Maximise total value with total weight ≤ W.
  • Example (W = 5 kg): A = 1 kg / 10 · B = 2 kg / 15 · C = 3 kg / 40. All three = 6 kg ✘.
  • Table: rows = items available, columns = capacity 0…W. Base: DP[0][w] = DP[i][0] = 0.
  • Recurrence: if item i fits → DP[i][w] = max( DP[i−1][w], value[i] + DP[i−1][w − weight[i]] ) (leave vs take); too heavy → copy DP[i−1][w].

🧳 Airline limit 5 kg: cargo loading, picking projects under a budget, choosing files for limited storage, selecting features for a sprint — each item is all-in or all-out.

🎤 Sample oral Q&A

QWhat does pseudo-polynomial time O(nW) mean?

AThe running time is polynomial in the numeric value of the capacity W, not in the length of the input (W takes only about log W bits). If W is huge, the algorithm is still very slow.

QWhy not just greedily pick the best value-per-kg items? bonus

AIt can fail for 0/1 items. In our example ratios are A = 10, B = 7.5, C ≈ 13.3: greedy takes C then A (4 kg, value 50), B no longer fits — but the optimum is B + C = 55.

⭐ Most important — expect this one

QExplain the 0/1 knapsack recurrence and solve the example (5 kg; A 1 kg/10, B 2 kg/15, C 3 kg/40).

ADP[i][w] = max(DP[i−1][w], value[i] + DP[i−1][w − weight[i]]) when item i fits, otherwise DP[i−1][w]; row 0 and column 0 are 0. Filling the table gives DP[3][5] = 55 by taking B and C (5 kg total). Time and space are O(nW).

🍬 Summary

Knapsack = for each item, compare 'leave it' vs 'take it'; the bottom-right cell is the answer.

  • Recurrence: max(leave, take)
  • Example answer = 55 (B + C)
  • O(nW) time & space, pseudo-polynomial

🔤 String Matching: Naive & KMP

From: Recursion & Algorithm Design

  • Problem: text T (length n), pattern P (length m) → find all starting positions where P occurs. Matches can overlap, so keep scanning after each hit.
  • Example: ABAB in ABABABCABAB occurs at indices 0, 2, 7.
  • Naive: try each of the n − m + 1 starting positions, compare until mismatch or full match. Worst case O((n−m+1)·m) ≈ O(nm). Simple, but repeats comparisons on repetitive text.
  • KMP: preprocess the pattern into an LPS table (longest proper prefix that is also a suffix) → time O(n + m). bonus On a mismatch, LPS says how far the pattern can slide without re-checking characters already matched.
  • Used in: search, text editors, compilers, cybersecurity, bioinformatics.
for i in range(n - m + 1):
    j = 0
    while j < m and text[i+j] == pattern[j]: j += 1
    if j == m: positions.append(i)

naive_search("COMPUTER SCIENCE", "SCI") → found at index 9

🔍 Ctrl+F in a document, spotting a DNA motif, a spam filter scanning for a phrase.

🎤 Sample oral Q&A

QWhat is the worst case for naive string matching?

AO((n−m+1)·m) ≈ O(nm) — e.g. text AAAA…A and pattern AAA…AB: at every position almost all m characters match before the final mismatch.

QCan matches overlap?

AYes. ABAB occurs in ABABABCABAB at 0, 2 and 7, so after a match you continue from the next start position, not past the whole match.

⭐ Most important — expect this one

QCompare naive string matching and KMP.

ANaive tries all n−m+1 starting positions and compares until a mismatch: O(nm), simple but repeats comparisons. KMP preprocesses the pattern into an LPS table so it never re-compares matched characters: O(n + m) overall.

🍬 Summary

Naive = try every position, O(nm). KMP = LPS table, no rechecking, O(n+m).

  • n − m + 1 start positions
  • Find all matches (they may overlap)
  • KMP: preprocessing + linear scan

🕸️ Graphs, BFS & DFS

From: Graphs · BFS · DFS · Dijkstra

  • Graph G = (V, E): vertices + edges. Can be directed/undirected, weighted/unweighted, cyclic/acyclic, connected/disconnected.
  • Adjacency list: O(V+E) space, fast neighbour loops, best for sparse. Adjacency matrix: O(V²) space, O(1) edge lookup, best for dense.
  • BFS — queue (FIFO), level by level. Mark visited when enqueued so nothing is queued twice. Gives fewest edges in unweighted graphs. Memory ~ width.
  • DFS — stack / recursion (LIFO), go deep, then backtrack. Used for cycle detection, topological sort, mazes, components. Memory ~ depth.
  • Time: both O(V + E) with an adjacency list (O(V²) with a matrix). Extra space O(V).
💬 BFS = ripples in a pond / rumour spreading / friends-of-friends / fewest flight hops. DFS = exploring a maze with a ball of yarn, backtracking at dead ends.

🎤 Sample oral Q&A

QAdjacency list or adjacency matrix?

AList: O(V+E) space, fast iteration over neighbours, best for sparse graphs. Matrix: O(V²) space, O(1) edge lookup, best for dense graphs.

QWhy does BFS find shortest paths in an unweighted graph?

AIt explores level by level, so the first time it reaches a vertex is via the fewest edges. DFS gives no such guarantee.

QWhy mark a vertex visited when you enqueue it in BFS?

ASo no vertex is put in the queue twice — otherwise it would be processed repeatedly.

⭐ Most important — expect this one

QCompare BFS and DFS.

ABFS: queue (FIFO), level by level, fewest edges in an unweighted graph, memory ~ width. DFS: stack or recursion (LIFO), goes deep then backtracks, memory ~ depth, used for cycle detection, topological sort, mazes and components. Both are O(V+E) on an adjacency list. On our graph BFS gives A B C D E F and DFS gives A B D E F C.

🍬 Summary

BFS = queue, wide, shortest hops. DFS = stack, deep, structure & cycles. Both O(V+E).

  • List: sparse · Matrix: dense
  • BFS shortest path only if unweighted
  • DFS: cycles, topological sort, mazes

🗺️ Dijkstra's Shortest Path

From: Graphs · BFS · DFS · Dijkstra

  • Goal: cheapest path from one source to every vertex in a graph with non-negative weights.
  • Greedy rule: always finalise the unvisited vertex with the smallest known distance, then relax its edges: if dist[u]+w < dist[v]: dist[v] = dist[u]+w. Uses a min-heap priority queue.
  • Complexity: binary heap O((V+E) log V) · simple array O(V²) (good for dense) · Fibonacci heap O(E + V log V).

🎤 Sample oral Q&A

QWhy can't Dijkstra handle negative edge weights?

AIts greedy step finalises the closest unvisited vertex, assuming no later path can be shorter. A negative edge could make a later path cheaper, breaking that assumption — so all weights must be ≥ 0.

QIs the path with the fewest edges always the cheapest?

ANo. In our example A→B→D→F has 3 edges but costs 15, while the cheapest A→C→B→D→E→F uses 5 edges and costs 13.

⭐ Most important — expect this one

QExplain Dijkstra's algorithm and its complexity.

ASet dist[source] = 0 and all others ∞. Repeatedly extract the unvisited vertex with the smallest distance (min-heap), finalise it, and relax its outgoing edges: if dist[u] + w < dist[v], update dist[v]. Needs non-negative weights. Time is O((V+E) log V) with a binary heap, O(V²) with an array, O(E + V log V) with a Fibonacci heap.

🍬 Summary

Dijkstra = greedy 'closest first' + relaxation. Non-negative weights only.

  • Min-heap → O((V+E) log V)
  • Relax: dist[u]+w < dist[v]
  • Unweighted → BFS; weighted → Dijkstra

🔌 Minimum Spanning Trees: Kruskal & Prim

From: Graph Algorithms: Spanning Trees & Ordering

  • Spanning tree = connects all V vertices with exactly V − 1 edges and no cycles. MST = the one with the smallest total weight.
  • Why greedy works: Cut property — the lightest edge crossing any split of the vertices is safe to add. Cycle property — the heaviest edge on a cycle (if unique) is never needed.
  • Kruskal: sort edges → take next lightest → skip if it closes a cycle (Union-Find) → stop at V−1 edges. O(E log E) = O(E log V).
  • Prim: start anywhere → add the cheapest edge leaving the tree → repeat. Array O(V²) · binary heap O(E log V) · Fibonacci heap O(E + V log V).

Kruskal: B–C 1 ✔ · A–C 2 ✔ · D–E 2 ✔ · A–B 4 ✘ (cycle) · B–D 5 ✔ → total 1+2+2+5 = 10. Prim from A: A–C, C–B, B–D, D–E.

🔌 Laying cable or roads to connect every village as cheaply as possible. Kruskal = "buy the cheapest links anywhere unless they make a loop"; Prim = "keep extending from the connected cluster". Also clustering and TSP approximations.

🎤 Sample oral Q&A

QWhy does Kruskal skip A–B (weight 4) in the example?

AA and B are already connected through C (via A–C and B–C), so adding A–B would close a cycle.

QWhen would you choose Kruskal vs Prim?

AKruskal for sparse graphs or when you already have an edge list; Prim (array version) for dense graphs or an adjacency matrix. Kruskal naturally handles disconnected input as a spanning forest; Prim needs a restart per component.

⭐ Most important — expect this one

QExplain Kruskal's and Prim's algorithms and why greedy works for MSTs.

AKruskal sorts edges and adds the lightest one that does not form a cycle (Union-Find), O(E log V). Prim grows a single tree by always adding the cheapest edge leaving it, O(E log V) with a heap or O(V²) with an array. Both are correct because of the cut property: the lightest edge crossing any cut belongs to some MST.

🍬 Summary

MST = connect everything with V−1 edges, minimum total weight. Kruskal = edges globally; Prim = grow a tree.

  • V − 1 edges, no cycles
  • Kruskal sparse · Prim dense
  • Cut property = proof of correctness

🧦 Topological Sorting

From: Graph Algorithms: Spanning Trees & Ordering

  • Topological order of a DAG (directed acyclic graph): for every edge u → v, u comes before v. It exists exactly when there is no directed cycle.
  • Kahn's algorithm (BFS): compute in-degrees → queue all in-degree-0 vertices → pop v, output it, decrement its neighbours, enqueue new zeros. If fewer than V vertices were output → cycle.
  • DFS-based: DFS from every unvisited vertex → push a vertex on a stack when it finishes → pop the stack for the order. An edge back to an active vertex = cycle.
  • Both: O(V + E) time, O(V) extra space. Used for build systems, course planning, task scheduling, dependency resolution.
Programming→Discrete Math→Data Structures→Algorithms→Machine Learning

One valid order from the slides (courses → prerequisites).

🧦 Getting dressed: socks before shoes, underwear before trousers. Course prerequisites. A build system compiling dependencies first.

🎤 Sample oral Q&A

QWhen does a topological ordering exist?

AOnly for a directed acyclic graph. With a directed cycle (A needs B, B needs A) no valid order exists.

QHow does Kahn's algorithm detect a cycle?

AIf the number of vertices output is less than V, some vertices never reached in-degree 0 — they sit on a cycle.

⭐ Most important — expect this one

QExplain Kahn's algorithm (and the DFS alternative) with complexity.

AKahn: compute in-degrees, queue all in-degree-0 vertices, repeatedly pop one, output it, decrement its neighbours' in-degrees and enqueue any that reach 0; fewer than V outputs means a cycle. DFS version: push each vertex on a stack when it finishes and pop for the order. Both run in O(V + E) time with O(V) extra space.

🍬 Summary

Topological sort = order tasks so prerequisites come first. Only possible on a DAG. O(V+E).

  • Kahn: in-degree 0 queue
  • DFS: push on finish, pop for order
  • Cycle ⇒ no valid order
